# 通信与跨端鉴权安全（0.4 / 0.5）

0.5 增加默认关闭的中心字节转发：外层逐设备固定公钥接入中心，内层仍由控制者和目标设备完成 DSHR2 双向认证。双方精确 `relayTargets` 才允许路由；路由权不是目标执行权，中心不能代替目标授权。预算、重连、撤销与手机边界见 [中心式互联指南](MESH.md)。

本文中的主机、名称和路径均为虚构示例。升级不会开启 server、发布端口、交换密钥或修改另一台主机。0.4 的默认拒绝策略有意比旧版严格。

## 信任模型与边界

- 每条直连都必须事先固定对方的 **X25519 公钥**。没有 TOFU、共享默认密码、自动信任、自签证书跳过或中继继承授权。
- 继续使用既有 DSHR2 的三路 X25519 密钥交换、HKDF-SHA256、双向 HMAC 持钥证明及分方向 AES-256-GCM；本次没有自创新密码套件。临时密钥提供前向保密，严格帧序号拒绝篡改、重排与重放。
- `DSHP1` 只选择公钥，**不是认证**。实际身份必须在 DSHR2 持钥证明完成后建立。日志/人工核验显示 `SHA256:` 加完整 64 位十六进制指纹；通过与连接通道独立的可信渠道核对。
- 受控端根据完整公钥指纹识别 principal，而不是请求中自称的名字。会话、运行、上传、取消和问答按 principal 隔离，知道别人的资源 ID 不等于获授权。
- level 3 是完全信任的远端代码执行能力，不是沙箱。一个拿到 level 3 的主机可通过 exec、工具或 agent 访问进程账号能访问的资源。不要向不可信主机授予它。

## 兼容握手必须显式开启

`allowLegacyHandshake` 默认 **false**：

- client 的顶层或单个 `peers.<name>`：默认只接受 key-selector ACK，失败不自动改走旧握手。显式设 true 才允许一次兼容重连，仍校验同一组 pin；ACK 后的认证错误、超时、拒绝和篡改不触发降级。
- server：旧客户端直接发送 DSHR2 仅在此项为 true 且采用单 pin 模式时接受。现代 selector 与单 pin 组合仍可使用，不必为了单主机设置而打开旧握手。
- 非空 `authorizedPeers` 只接受列出的身份，绝不回退到 legacy pin；错误配置也不会恢复旧授权。

推荐双方升级到 0.4 后保持 false。仅为明确的旧端短期打开，完成升级后关闭。双端升级和本机重启由操作者分别安排，本任务不自动部署。

## 每身份的细分授权

在 server 的 `authorizedPeers` 中配置各控制方：

```yaml
authorizedPeers:
  studio:
    peerPublicKeyFile: 'C:/keys/studio.pub'
    maxPermission: 1
    readRoots: ['C:/shared/research']
    allowedOps: ['ping', 'sysinfo', 'fs.stat', 'fs.list', 'fs.get', 'fs.hash', 'references.list']
    disabled: false
    validUntil: '2030-12-31T23:59:59Z'
```

- `maxPermission` 新条目默认 1；实际权限是全局与条目上限的较小值。全局旧默认 3 仅保留已有行为，不等于所有新 peer 获得 3。
- `allowedOps` 是精确协议操作名列表，不支持 `*`，最多 64 项、每项 64 字符。空列表沿用权限级别规则；非空列表再取交集，不能提权。使用工具时要把查询和相应的取消操作一并考虑。
- `disabled: true` 暂停该公钥。`validUntil` 为空表示不限授权日期；非空必须为带明确 Z 或数值时区的 RFC3339 时间，非法日期、无时区、未知 `-00:00` 偏移和闰秒均拒绝。
- level 1/2 的文件读取要显式配置 `readRoots`（最多 32 个绝对路径，每个最多 4096 字符，不支持通配符）；空列表禁止读取文件，不再默认允许遍历整机。`fs.read/get/hash/stat/list` 使用本机真实路径进行根目录包含检查。level 2 的写入另外受 `workspaceRoot` 限制，空写根不授予写入。
- legacy 单 pin 模式使用 server 顶层 `readRoots`。level 3 保留全信任含义。工作区和插件目录发现仅返回元数据，不是文件读取授权。
- 权限、操作列表、根目录、禁用和期限被重新核验；撤销或策略变更会停止该身份的运行、工具、上传及受驱动 agent，关闭旧连接并使排队的旧代任务无效。已经产生的外部副作用不能回滚，取消也依赖被调用工具遵守 AbortSignal；永久拒绝后续操作不依赖它遵守。

请不要把系统盘根、DSH home、私钥或凭据目录放入可读根。受限文件访问采用 canonical containment 和危险路径拒绝；它不是对拥有本地并发改链接权限的攻击者的 OS 级隔离。敏感部署应再用独立低权限账号、容器或 VM。

## 连接、限流和抗资源耗尽

server 保持默认仅绑定 `127.0.0.1`；公网侧继续使用自己的 VPN、防火墙和隧道。

| 配置 | 默认 | 作用 |
|---|---:|---|
| `maxConnections` | 64 | 包括未认证连接的总数 |
| `maxPendingHandshakes` | 8 | 同时等待认证的连接数 |
| `maxConnectionsPerAddress` | 16 | 每来源地址的连接上限 |
| `maxHandshakesPerMinute` | 120 | 每来源地址令牌桶容量与每分钟补充速率，允许受限突发 |
| `maxTrackedAddresses` | 1024 | 失败与限流表的内存上限 |
| `maxHandshakeFailures` | 8 | 失败冷却阈值 |
| `lockoutSeconds` | 900 | 失败后的冷却时间 |
| `handshakeTimeoutMs` | 15000 | selector 和握手的总预算 |
| `maxInFlightPerPrincipal` | 16 | 跨同身份所有连接合计的普通请求并发上限 |
| `maxSessionMs` | 3600000 | 已鉴权连接最长寿命 |

配置被约束在硬范围内，不能用 0/NaN/Infinity 关闭预算。取消和问答不被普通请求并发队列饿死。停止/卸载会清理尚未认证的 socket，而不只是关监听入口。多个控制方经同一隧道地址进入时会共享地址预算，应在可信边缘再做限流，不要靠改成无限来解决。

client 同样限制连接寿命，复用前重新核验 pin 与本地身份，包括密钥文件更新；旧对象在配置替换后永久退休。已有会话绑定原主机及密钥/endpoint，不会因别名复用、权限降低或默认主机切换悄悄迁移。

## 帧、请求与文件传输

- 默认单帧最多 **32 MiB**，协议库硬上限 256 MiB。不是所有 API 都适合单帧大文件；优先使用分块传输。
- 帧一旦开始接收，header 和 body 共用默认 **30 秒**总预算；未开始新帧的空闲连接可以等待，但仍受连接寿命限制。
- 使用 paused TCP stream 和背压，不维护无限 data-push 缓存。发送队列默认 64 条且有字节预算；并发 recv 被拒绝。计数器在安全整数范围结束前停止，绝不重用 nonce。
- 非法 UTF-8、非 JSON object、畸形帧、错误认证标签、截断或计数异常会终止连接，释放等待者并尽可能清零 Buffer 密钥。JavaScript/运行时的所有内存副本不能保证被安全擦除。
- RPC 请求 ID 必须是严格递增正安全整数，操作名和控制消息有独立 envelope 校验；未知操作不能靠原型属性命中处理器。
- 断线后只有明确列出的观察性读取可自动重试。exec、驱动 agent、工具调用、写入和提交的结果不明确时，不会自动重放以免重复执行。调用方需查询状态或人工确认。
- base64 分块严格检查编码及输入长度，gzip 解压按本次请求的 chunk 大小限制输出，不能由对端谎报长度提升限额；上传同样有大小/数量/TTL 和校验。

## 密钥文件与轮换

- 私钥生成使用独占创建，存在或并发出现的身份不会被覆盖；文件大小最多 16 KiB，拒绝最终路径符号链接和非普通文件。
- POSIX 私钥文件要求 owner-only 权限（例如 `chmod 600`）；新建目录使用 0700，私钥使用 0600。Windows 沿用账号/目录 ACL，**本插件没有自动强化或证明 Windows ACL**；操作者应检查继承权限。
- 不接受错误算法/角色的 PEM，不把私钥误作 pin；原始 key 必须是 64 位 hex 或规范的 32 字节标准 base64。带杂字符、异常 padding 的宽松编码会拒绝。
- 轮换任一端私钥、公钥 pin 或授权表后，旧连接不能继续用旧信任。不要先删掉旧私钥指望自动生成“修复连接”；应先通过独立可信渠道核对新指纹再显式配置。
- 私钥泄露时，应在所有接收方禁用/移除该 principal、轮换密钥，检查审计并撤销泄露的其他凭据。服务重启不是撤销私钥。

## 验证与剩余风险

新增测试覆盖帧篡改、重放、方向混淆、截断、超大帧、计数耗尽、慢帧、发送背压、严格密钥、连接限额、授权过期/撤销和本机权限变更等。测试属于本地和 loopback 验证，不等同于第三方密码学审计、渗透测试或公网压测。预算和限流不能代替边缘 DDoS 防护；获授权的大文件、大目录和高开销工具仍需宿主资源配额与监控。

`caps.call` 仍是 level 3 的直接工具本体调用，不自动经过对端 tools 的 guards、pre/post hooks 或审批链；工具自身检查仍在。需要人工审批时应使用受控 preset/宿主策略，或设置 `capabilities: false` / `deniedTools`，不要把 direct call 当成经过审批的调用。本插件不提供 2FA 或每次高危操作的人类确认。审计日志是本地普通文件，不具备防篡改或第三方见证。

本插件不解决受信 level 3 主机失陷、宿主 OS 已被控制、VPN/隧道管理凭据泄露、日志泄密、磁盘耗尽或 OS 防火墙配置错误；也不提供证书 CA/PKI、硬件密钥或远程硬件证明。需要这些能力时，应在外层建立成熟的身份与网络安全基础设施，而不是关闭 pin 验证。
