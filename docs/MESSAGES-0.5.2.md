# 0.5.2 message transport and offline validation

This independent staged copy preserves the original dsh-remote repository attribution and MIT license. It has not been installed into the live profile and no real peer, model, external delivery or remote exec was used for this change.

## Data and compatibility

- `replyFormat: committed-assistant-v1` and `replies` identify only committed, non-interrupted `assistant/message` rows with actual `source.kind:model`, stable message identity, event sequence/time and turn/step coordinates. Each public text/image/file block is copied in order; reasoning, tool blocks, adapter replay state and stream attempts are excluded. Text within a message is not split into invented messages.
- `reply` remains a string for old consumers but now joins every retained message's text with a blank line. Media-only rows remain in `replies`, not lost when their text is empty.
- Foreground/answer-question results keep the peer arrays. Background records deep-copy and preserve arrays. The remote provider and delegation tool carry arrays in their result, while provider compatibility `output` stays text: a remote attachment id is not a local attachment id.
- Presenters are pure views over the persisted tool result, labelled per remote assistant message and model. They neither append local assistant events nor use `appendPluginRecord`. Without bubble, the standard tool result still lists each reply and durable media reference.
- An old peer remains `legacy-text`, with no claimed message boundaries, message ids or reconstructed earlier messages. Unversioned or invalid arrays are not trusted; the raw legacy string is the explicit fallback. Both ends must upgrade to get authentic arrays.
- `sysinfo.features` advertises replies and note modes. A v0.5.2 client omits mode for a legacy peer and explicitly reports queue-only behavior; an explicit steer request is refused when that capability is not advertised. Only an exact pre-handler unknown-op error allows note-to-prompt fallback; arbitrary `unsupported`, timeout or receipt failures never cause resubmission.

## Input source, sidecar and lifetime

`MessageSourceMap` is officially merge-extensible in DSH 0.2.2-rc.1: an external input can be a user-role message without claiming local human source. New remote inputs use `kind:dsh-remote`, version 1, the authenticated principal, wire session id, operation and trace id; when the optional `superAgentIo` adapter admits the input, IO's public `kind:super-agent-io` source (transport, binding, endpoint, trace, external id) is used instead. The model's output source remains the actual provider/model.

The official `storageDomain` facility owns the `dsh_remote_message_traces` domain, version 1, per-record layout. A trace contains its principal, local scoped session id, wire session id, message id, eventual committed event seq/time, requested/actual inbox mode and admission state. The record key hashes the complete principal/session/message tuple rather than using paths or truncated ids. This is transport metadata, not replacement Session history. No data is placed in provider `replayState`.

The sidecar persists intent before the inbox wake. Missing facility or an initial write error rejects before that side effect. A wake failure is ambiguous and records `unknown`; receipt failure tells the caller not to resend. No admission is automatically replayed. Post-commit observations anchor the message's seq, with serialized writes preventing a later accepted receipt from overwriting a committed anchor. Unload closes and drains the domain. Older history without a trace retains unknown transport facts; no synthetic backfill is claimed.

Cold remote sessions continue the authenticated `scopedSessionId`, owner, permission checks, remote setup, preset and model lifecycle. `agents.resume` creates only after `SessionPersistenceNotFoundError` names that exact session (or official exact `session/not-found`); malformed/corrupt, writer-held, unsupported format, generic errors and cancellation propagate. `sessionController.resolveAgent` was inspected, but its ordinary-session API has no remote setup/preset/owner parameters and cannot replace this path without changing those obligations. No borrowed ordinary Agent is disposed or adopted. The current release's `installModelSelection(agentCtx)` listener is used; default options are supplied through `agentOptions`, while recorded selection wins.

## Scope and optional integration

The encryption suite, handshake pinning, live authorization/revocation checks, ACLs, remote fs and deterministic one-local-chat/one-remote-session rules are unchanged. Steering uses official `Agent.steer` only; it does not cancel an already prepared LLM request. `auto` maps busy to steer and idle to followup; returned mode/processing fields are the actual placement.

`superAgentIo` remains an optional runtime peer, never a dependency. With `dsh-remote-server.superAgentIo: true` and a compatible `ctx.superAgentIo` v1 service, controller prompts/notes are admitted through `io.receive` into the same scoped Session dsh-remote already created, so the committed row carries IO's real `super-agent-io` producer source. The adapter registers one `dsh-remote` transport plus one stable principal+Session binding; every committed assistant message IO routes is delivered as one separate frame. The client buffers those frames and merges them into a valid committed `replies` array by `sessionId + messageId`, never by sentence splitting, synthesized assistant rows or relabelled tool output. Only a definite pre-send refusal (disabled service, missing binding, content policy) falls back to the original `kind:dsh-remote` path; an `unknown` admission is never replayed. Without the service, with the switch off, or with IO's own gates off, the existing remote path runs independently. Remote attachment ids remain references to the remote Session and are not automatically submitted to local attachment admission. No assistant row is appended to a running main chat and no real peer is triggered by the adapter.

On the controller side, `superAgentIoInbound` (default false) handles frames that arrive without a waiting RPC. It matches the authenticated peer's current authority and exact session family, then calls `receive` on the local Session that memory maps to that wire Session. This external input may start a normal local model turn. The binding uses `receiveOnly:true` and `sendEnabled:false`, keeping local replies in the canonical Session without creating outbound deliveries. A stable external message id encodes the peer, wire session and remote message id (hashed only when over the public bound). Structured `replySource` preserves the peer, provider/model and remote message coordinates alongside the original message text. Image and file blocks remain labelled remote references. The RPC and asynchronous paths suppress already handled frames, and an `unknown` admission is not retried. Without the service or with the switch off, the original RPC/in-memory path remains available.

## Build coordination

`tools/build.mjs` still supports `DSH_BUILD_ROOT` for an exact development checkout containing esbuild. All DSH services remain external and preserve installed runtime identity; zod is an explicit peer. `DSH_FS_ALIAS_SOURCE_ROOT` is a separate, explicit opt-in for the lead's final reviewed foundation build: only the peer-fs entry inlines the matching release's `dsh-fs-local` and `dsh-fs-sandbox` implementation, while `dsh-fs`/FsError and other services remain external. The source root version is checked; ordinary builds do not turn this on or patch peer-fs logic. Every peer-fs build also rewrites `lib/peer-fs-0.5.2.js` as a re-export of `lib/peer-fs.js`, and both package subpaths (`./peer-fs` and `./peer-fs-0.5.2`) resolve to `lib/peer-fs.js`, so they share one ESM generation and keep the named `FederatedFileSystem` plus the shared Cordis/FileSystem/FsError identity instead of inlining a second class family. Direct `file:///…/lib/peer-fs-0.5.2.js` references get the same re-export rather than a stale full bundle. `chokidar` and `koffi` remain external exact peers (native modules are never bundled), and the inline local implementation's `dsh-fs-patch` remains a declared external peer. The final opt-in foundation build was performed after lead confirmed alias source freeze; its built filesystem test passed real temporary local alias read/write/edit, identity, stale guard, sandbox refusal, symlink escape refusal, owner unload and unchanged remote URI parsing without making peer requests. Installation remains lead-coordinated.
